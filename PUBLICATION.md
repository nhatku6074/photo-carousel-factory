# Public launch guide

## Repository positioning

Suggested repository name:

`photo-carousel-factory`

Suggested description:

> Model-agnostic Codex Skill that turns product references into publish-ready five-slide Photo Mode carousels with deterministic captions and QA.

Suggested GitHub Topics:

`codex-skill`, `ai-content`, `tiktok`, `photo-mode`, `social-media`, `ecommerce`, `content-automation`, `image-generation`, `creator-tools`, `python`

Suggested first release:

`v1.0.0 — Model-agnostic carousel planning, caption rendering, QA, and ZIP packaging`

## Target audiences

1. Solo creators who need repeatable content without a designer.
2. TikTok Shop and ecommerce operators producing multiple product angles.
3. Affiliate creators testing several narratives for the same product.
4. Social agencies standardizing delivery across clients.
5. AI builders who need a deterministic layer after image generation.

Lead with the visible output for creators and ecommerce operators. Lead with the JSON schema, tests, and provider neutrality for developers.

## Recommended growth ideas

### 1. Engineering as marketing: free Skill + demo

Why it fits: the repository is itself a usable free tool and demonstrates the workflow better than a long sales page.

How to start:

- Pin the repository and keep the demo contact sheet above the fold.
- Publish one real but permission-cleared example per week.
- Add a short “made with Photo Carousel Factory” link to public examples when appropriate.

Expected outcome: qualified GitHub Stars, installs, issues, and contributed frameworks.

Resources: 2–3 hours for launch polish, then about 1 hour per weekly example.

### 2. Short-form build-in-public demo

Why it fits: the transformation from product reference to five numbered slides is visual and understandable in under 30 seconds.

How to start:

- Record a 20–30 second screen capture: input → generated bases → caption render → contact sheet.
- Post the same vertical clip on TikTok, X, LinkedIn, YouTube Shorts, and Xiaohongshu with platform-native copy.
- Put the GitHub link in the first comment and profile.

Expected outcome: creator discovery beyond the developer audience.

Resources: one afternoon for the first video; reuse it across channels.

### 3. Community-first launch

Why it fits: Codex, AI automation, ecommerce, and creator-tool communities already discuss repeatable workflows.

How to start:

- Share a technical breakdown in relevant GitHub, Reddit, Discord, and forum communities where self-promotion is permitted.
- Ask for one narrow form of feedback: provider support, caption styles, or schema improvements.
- Turn repeated questions into issues and roadmap entries.

Expected outcome: higher-quality feedback, contributors, and authentic word of mouth.

Resources: 2–3 thoughtful posts and ongoing replies; no paid budget required.

### 4. Template and framework releases

Why it fits: new copy frameworks and fictional examples provide recurring release reasons without bloating the core Skill.

How to start:

- Release one themed framework pack each month: ecommerce mistakes, routines, product education, organization, or gifting.
- Keep examples fictional or permission-cleared.
- Tag each release and include before/after contact sheets.

Expected outcome: repeat visitors, release subscribers, and long-tail search traffic.

Resources: 2–4 hours per monthly framework pack.

### 5. Partnerships with model and workflow communities

Why it fits: provider neutrality makes the Skill a useful example for image-model vendors, ComfyUI builders, and automation platforms without locking into one partner.

How to start:

- Publish a neutral benchmark using the same product-reveal prompt across several providers.
- Invite maintainers to contribute provider notes without placing credentials in the core Skill.
- Offer a co-authored demo that keeps the repository open and vendor-neutral.

Expected outcome: backlinks, partner distribution, and provider-specific contributors.

Resources: a benchmark brief, permission-cleared reference asset, and 1–2 partner conversations.

## Four-week launch sequence

### Week 1 — Foundation

- Publish the repository and `v1.0.0` Release ZIP.
- Pin the repository and verify the README preview on desktop and mobile.
- Open three roadmap issues: caption styles, multilingual fonts, and provider comparison notes.

### Week 2 — Demonstration

- Publish the 30-second build-in-public clip.
- Share a technical post explaining why captions are rendered after image generation.
- Invite ten relevant creators or automation builders to test the ZIP.

### Week 3 — Community proof

- Publish the first user-created or permission-cleared example.
- Add FAQ answers based on real installation questions.
- Share one provider-neutral comparison focused on the product-reveal slide.

### Week 4 — Compounding distribution

- Release a small copy-framework update.
- Write a searchable tutorial: “How to build TikTok Photo Mode carousels with any image model.”
- Review traffic, Stars, ZIP downloads, completed examples, and issues; prioritize the next release from observed demand.

## Success metrics

Track:

- repository visitors to Stars;
- Release ZIP downloads;
- successful demo renders;
- issues from real users;
- external examples created;
- contributors and merged pull requests;
- referral traffic from short-form demos and communities.

Avoid optimizing only for Stars. The strongest signal is a user producing and publishing a complete carousel.
